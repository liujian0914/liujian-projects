# 01 · 全流程 SOP

> 这是六阶段流程的完整版。SKILL.md 给的是骨架，这里给每个阶段的具体动作、判断标准、以及"卡住时怎么走"。

适用于：大创申请书、国创赛申报书、挑战杯调研报告、课题申报书、奖学金材料里带研究设计的部分、课程作业申报书。

---

## 阶段 0 · 开工前五分钟

做三件事，省后面三小时。

**① 环境自检**

```bash
pf doctor
```

缺 `olefile` 说明处理不了旧 `.doc`；缺 `pywin32` 说明做不了 COM 转换和 PDF 导出；`com` 为 `false` 说明本机没装 WPS/Word。这几项缺失不影响出图和改文本，但影响"旧 doc 转换"和"目录页码"，先知道比中途崩了好。

**② 建工作区**

```bash
pf init ./项目名
# fig/  自绘图表      img/  原始素材      bak/  每轮备份      out/  交付物
# proposal.json 项目参数
```

**③ 问清三件事**（一次性问完，别边做边问）

- 交什么格式？只要 docx，还是 docx + pdf。
- 有没有官方模板？模板是"结构框死只填内容"，还是"仅作参考"。
- 哪些字段要我填、哪些他填？典型要他填的：民族、出生年月、指导教师及电话、项目编号、学号、联系方式。

## 阶段 1 · 定基

### 1.1 摸清原始材料

```bash
pf probe 原文件.docx --out out/基线.md
```

看四个数：字数、段落数、表格数、内嵌图数。再看标题列表和图宽分布。

**判断文件类型**：

- 标题列表为空 + 段落数很少 + 表格数=1 到 6 → 正文装在表格里，必须用穿透遍历（`pf` 已处理）。
- 段落数很多但字数很少 → 大量空段落在占位，多半是模板没填。
- 内嵌图 0 但文件体积几十 MB → 图片在别的地方（可能是嵌入对象、也可能是压缩过的背景）。

### 1.2 找权威数据源

申报书里每一个数字都必须能指回去。把源数据整理成一份 `data.md`：

```markdown
## 调研样本
- 有效样本 103 份
- 结构：普通农户 47 / 家庭农场 18 / 合作社 17 / 龙头企业 9 / 行业协会 6 / 基层监管所 6

## 六维得分（百分制）
| 品类 | 标志认知 | 标志使用 | 标准执行 | 带动效果 | 品牌认可 | 政府监管 |
|---|---|---|---|---|---|---|
| 苹果 | 75.33 | ... | 40.24 | ... | ... | ... |
```

**这一步不做，后面必然出现图与表打架。** 真实事故：图里四个产品的执行分全画成 40，表里是 40.24/62.05/40.27/40.44，两个数一算，结论方向都反了。

### 1.3 列缺口清单

把所有需要本人确认的信息列成一张表，一次性发过去。不要分五轮问。

### 门禁

能用一句话说清："这份申报书的核心结论是什么，用哪三个数据支撑。"说不出来，说明材料还没读懂，回 1.1。

## 阶段 2 · 搭骨

### 2.1 对齐模板

```bash
pf probe 模板.docx --out out/模板结构.md
pf probe 自稿.docx --out out/自稿结构.md
```

逐项比对：标题数量、层级、顺序；表格数量与结构；必填栏位。

大创申请书的典型骨架（见 `templates/outline-dachuang.md`）：封面 → 填写说明 → 基本情况表 → 立项依据（研究目的/内容/方法/创新点/进度/预期成果）→ 经费预算 → 三个意见栏。

**模板的表格是钉死的**：基本情况、经费预算、意见栏不要加行、不要合并单元格、不要改列宽。改了就等着被打回。

### 2.2 处理"正文在表格里"

如果正文整体在一个 1×1 单元格里，编辑时所有操作都要走穿透遍历。自己写脚本时注意：

```python
# ❌ 错：正文全在表格里，这里几乎是空的
for p in doc.paragraphs: ...

# ✅ 对：XML 树遍历，穿透表格
for el in doc.element.body.iter(qn("w:p")):
    p = Paragraph(el, doc)
```

### 2.3 编号体系定下来

先决定章节目录用几级、图和表怎么编号、附录放什么。**中途改编号体系等于全文重排。**

常用：`1 / 1.1 / 1.1.1` 三级标题；图按章编（图 1-1）或全文连续（图 1…N）。全文连续更省事，也更好查重号。

### 门禁

标题数量、层级、顺序与模板一致；表格数量一致；编号体系已确定且写进 `proposal.json`。

## 阶段 3 · 填肉

### 3.1 每节的四件套

一节合格的内容，结构是固定的：

```
结论（这节得到什么）
  ↓
问题（为什么需要知道这个）
  ↓
方法（怎么得到的：样本、口径、对照）
  ↓
证据（数据、案例、文献）
  ↓
边界（什么情况下不成立）
```

缺"边界"是学生申报书最常见的短板。写上"本研究未覆盖 X 情形，结论外推需谨慎"，可信度立刻上一档。

### 3.2 五条写作纪律

1. **先给结论再解释。** 每节第一段就说明本节得到什么。不要从"随着…的不断发展"起手。
2. **数字带口径。** "103 份有效样本"而不是"大量样本"；"认知 75.3 分、执行 40.2 分"而不是"存在明显落差"。
3. **区分事实与推断。** 推断写明"可能的原因是"，并给出可检验方向。
4. **不编数据。** 缺数据就换论证方式（案例、访谈、文献），不要造。真要用估算值，标注"估算口径"和推算过程。
5. **每段只有一个主张。** 一段里塞三个论点，读者一个都记不住。

### 3.3 扩写的正确方式

从 7,500 字扩到 14,750 字，不是把句子拉长，是补这七类内容：

- 机制拆解（为什么这个变量会影响那个结果）
- 方法细节（抽样框、样本量依据、信效度方案、对照组设置）
- 数据解读（不重复表里的数，而是解释数之间的关系）
- 文献分歧（关于这点有几种说法，本文站在哪边、为什么）
- 技术选型取舍（三条路各有什么代价，为什么选这条）
- 局限与外推边界
- 风险与应对

每一类都能实打实加 300–600 字，且不是注水。

### 门禁

通读一遍，每段都能回答"这段想证明什么"。答不出的段落删掉或重写。

## 阶段 4 · 配图

见 `03-figures.md`，这里只说流程位置。

### 4.1 先定图清单

在写正文时就把"这里需要一张图"标出来，形成清单：

```
图1 六维指标结构（认知→使用→执行；带动→认可→监管）
图2 研究框架总览（五条线索 + 验证结论回流）
图3 四类产品认知与执行对比
图4 六类主体执行力矩阵
图5 项目进度里程碑
```

清单先行，避免"写到哪想到哪"，最后图片分布头轻脚重。

### 4.2 出图并插入

```bash
pf chart --spec fig/图3.json
pf whitebg img/ip.png                    # 有透明通道的先压白底
pf hstack a.png b.png --out fig/ab.png   # 两张竖图合成一张
```

插入位置三条纪律：

- **`addnext` 到题注之后**，不要 `addprevious`。
- 图宽统一 12.2cm（整幅宽的图）。
- 单图单题注。两张图分别插会把后一张的题注挤到下一页。

### 4.3 平衡图片分布

检查"前半 1 张/页、后半 1.6 张/页"这种头轻脚重。补救办法：在前半补一两张结构性图（框架图、指标结构图），而不是把后面的图往前挪——挪图会让正文失去引用点。

### 门禁

正文每张图都有"如图 N 所示"的引用；图号连续；图宽中位数 ≈12cm；无一张图孤零零挂在页首而题注在下一页。

## 阶段 5 · 修面

### 5.1 顺序很重要

```bash
pf tables  稿.docx --header      # ① 先修表格：会改变分页
pf renumber 稿.docx              # ② 再重排编号
pf images  稿.docx --action width --cm 12.2   # ③ 再统一图宽：也会改变分页
pf toc     稿.docx               # ④ 最后算目录页码：必须在前三步之后
```

目录页码放最后，因为它依赖最终分页。前面任何一步改了分页，页码都要重算。

### 5.2 参考文献

先查正文有没有 `[n]` 引用：

```bash
pf qa 稿.docx        # 报告里的"参考文献"一节会给出条目数与最大编号
```

有条目未被引用、或引用编号超过条目数，都说明要连正文一起改。规则见 `06-citations.md`。

### 5.3 封面

封面是最容易露馅的一页。三个高频问题：

| 问题 | 原因 | 修法 |
|---|---|---|
| 标签和值粘在一起（"项目负责人张三"） | 模板漏了空格 | 空格加在**标签 run**（无下划线）末尾 |
| 项目名折行后下划线断开 | 值末尾有填充空格 | 去掉值末尾空格，下划线止于文字 |
| 项目名占两行 | 字号过大 | 降字号到 12pt，清首行缩进与左缩进，压成一行 |

> 中文字符型缩进（`w:firstLineChars`）与磅值缩进（`w:ind` left+hanging）优先级不同，**混用会让整块位移**。模板用哪个就跟哪个，不要"改良"。

### 门禁

`pf qa` 报告里：图/表编号连续、文献一一对应、无整段加粗、无重复标点、无占位符。

## 阶段 6 · 交付

### 6.1 自检与导出

```bash
pf qa 稿.docx --out out/自检报告.md
# 导出 PDF（Windows COM）
```

导出后**逐页看一眼**。重点三处：图有没有被裁、题注有没有掉页、目录页码对不对。

### 6.2 交付包

```
项目名/
├── 项目名（修订版）.docx
├── 项目名（修订版）.pdf
├── 改动说明.md          改了哪几处、为什么、哪些留空待填
├── 自检报告.md
└── fig/                 图表源文件（对方可能还要改）
```

### 6.3 三条纪律

- **不覆盖原文件。** 输出永远另存"（修订版）"，原件保留。
- **提醒对方关文档。** 出现 `~$xxx.docx` 锁文件说明他正开着，他不关、你一交付，他一保存就覆盖。
- **改动说明要写。** 只交文件不交说明，对方下次改的时候会把你的处理全部推翻。

## 卡住时怎么办

| 卡在哪 | 走哪条路 |
|---|---|
| 文件打不开，报 relationship 错误 | 是 OLE 复合文档，先 `pf convert` |
| 标题取不到，做不了目录 | 标题没用样式，先套样式，或手工做目录 |
| 题注怎么调都掉到下一页 | WPS 不遵守 keepNext，缩图或删上方文字 |
| 图与表数字不一致 | 回 `data.md` 查权威源，问对方以哪个为准 |
| 目录页码怎么都对不上 | 先跑完 tables/renumber/width 再算页码 |
| 全文都是 AI 味 | `pf style` 看命中项，按 `07-humanize.md` 逐类改 |
| 文献查不到 | 换一篇能查到的，不要编造卷期页码 |
