# 大创 PPT 策略

> 通用方法见 `ppt/PLAYBOOK.md`。本文件只写大创特有的部分。

## 一、定位

**立项答辩**：讲"这笔钱给我们，我们能按期做出东西"。

大创**通常不需要 PPT**。只有校级答辩环节才可能要，5–8 分钟，评委是本校老师。

## 二、硬指标

| 项 | 值 |
|---|---|
| 要不要 | **通常不需要**；校级答辩可能要 |
| 页数 | 12–18 页（比大挑少，因为时间短） |
| 时长 | 5–8 分钟 |
| 风格 | **学术简约风**（最安全，不花哨） |
| 动画 | 可有可无，**不需要刻意做** |

## 三、如果真要做，讲这五件事

大创立项答辩的评委只关心五个问题，PPT 就按这个顺序讲：

| 顺序 | 讲什么 | 对应页数 |
|---|---|---|
| 1 | **做什么**（一句话说清项目） | 1–2 页 |
| 2 | **为什么值得做**（背景+痛点） | 2–3 页 |
| 3 | **怎么做**（技术路线图，**最重要**） | 3–4 页 |
| 4 | **做得到吗**（团队+进度+经费） | 3–4 页 |
| 5 | **做出来是什么**（预期成果） | 1–2 页 |

## 四、决胜页：技术路线图

大创和别的赛道最大的区别：**评委最想看的是"你打算怎么一步步做出来"**。

**做法**：
- 用 `pf chart --spec` 的 `framework` 类型，画成分层流程图
- 每一步写清：输入 → 动作 → 输出
- 标出**关键里程碑**和时间节点
- 不要写成"研究内容一、二、三"的文字罗列

**示例结构**：

```
阶段一（1-3月）  文献调研 + 需求分析
   输入：XX 领域文献 200 篇、访谈 20 人
   输出：需求分析报告 1 份

阶段二（4-7月）  模型/系统设计与实现
   输入：需求分析报告
   输出：原型系统 1 套

阶段三（8-10月） 实证验证
   输入：原型系统 + 试点数据
   输出：验证报告 + 论文初稿

阶段四（11-12月）总结与结题
   输出：结题报告 + 论文投稿 + 软著申请
```

## 五、骨架

```
P1   封面（项目名 + 负责人 + 指导教师 + 学院）
P2   目录
P3   项目简介（一句话 + 一张图）
P4   背景与痛点
P5   国内外现状（简要）
P6   研究目标（3 条，可考核）
P7   ★ 技术路线图（决胜页）
P8   研究方法
P9   创新点（2-3 条）
P10  进度安排（甘特图）
P11  团队分工
P12  经费预算
P13  预期成果
P14  风险与应对
P15  致谢
```

## 六、视觉风格

**学术简约风**：

```yaml
主色: "#333333"      # 深灰
强调: "#C62828"      # 单点红（只用于关键数字/关键结论）
背景: "#FFFFFF"
辅助: "#F5F5F5"      # 浅灰卡片
```

**不要用**：
- 花哨的渐变
- 大面积的实景照片（大创不是大挑，不需要证明"我去了"）
- 复杂的动画

## 七、动画

大创答辩时间短（5–8 分钟），**动画能省就省**。

如果一定要加：
- 技术路线图：分层依次出现（每层 0.3s）
- 进度甘特图：条状从左生长
- 其他页：不加

**总动画时长控制在 15 秒内**。

## 八、和大挑 PPT 的区别

| | 大创 | 大挑 |
|---|---|---|
| 要不要 | 通常不要 | 必需 |
| 时态 | 将来时 | 完成时 |
| 决胜页 | **技术路线图** | **调研规模数据墙** |
| 风格 | 学术简约 | 田园实景/商务数据 |
| 页数 | 12–18 | 18–22 |
| 动画 | 能省就省 | 关键页必需 |
| 照片 | 不需要 | **必需真实照片** |

## 九、交付前自查

- [ ] 页数 12–18
- [ ] 有技术路线图，且每步有输入输出
- [ ] 进度安排是甘特图，按月排，有里程碑
- [ ] 经费每笔有依据
- [ ] 预期成果可实现（不吹）
- [ ] 全文用"将"不用"已"
- [ ] 动画克制（<15s）
