# competition-forge · 中文竞赛全流程工坊

> 前身 `proposal-forge`（v1.1.0）。v2.0 起从"申报书工坊"升级为**多赛道竞赛工坊**：
> 同一套工具链，按赛事分别加载评审偏好、章节骨架、PPT 策略与配图规范。

把一个想法做成**评委愿意读下去、并且能讲清楚**的参赛作品。不只是文档——文档、PPT、图、文献、语言，各自做对，再拼成一个整体。

---

## ⛔ 第零步（强制）：先定赛道，再动手

**本技能不允许在未确定赛道的情况下开始任何产出。** 这不是建议，是硬门禁。

### 为什么必须定赛道

不同赛事的评价体系不是"同一份东西换个封面"：

| | 大创 | 大挑 |
|---|---|---|
| 官方全称 | 国家级大学生创新创业训练计划 | "挑战杯"全国大学生课外学术科技作品竞赛 |
| 本质 | **项目立项**：要钱、要按期结题 | **成果竞赛**：已有成果去比拼 |
| 评委看什么 | 可行性、创新性、经费合理性、能不能结题 | 选题价值、调研方法、数据真实性、社会效益 |
| 核心材料 | 申请书（1.2–1.6 万字） | 社会调查报告（2 万字以上）+ 答辩 PPT |
| 有没有 PPT | 通常不需要 | **必需，且是决胜环节** |
| 常见死法 | 经费编不圆、进度排不出 | 数据来源说不清、结论撑不住 |

按大创的写法去做大挑，会死在"没有真调研"；按大挑的写法去做大创，会死在"不像个项目"。

### 怎么定赛道

```
1. 用户明确说了比赛名 → 直接用，进对应赛道
2. 用户没说 → 必须问，不许猜、不许默认
3. 用户说的比赛还没建赛道 → 走「新增赛道」流程（见 competitions/README.md）
```

**提问模板**（只在用户没说时用，不要啰嗦）：

> 这份材料是投哪个比赛的？目前支持：
> - **大创**（国家级大学生创新创业训练计划）
> - **大挑**（"挑战杯"全国大学生课外学术科技作品竞赛）
>
> 两者评审口径和材料形态差别很大，定了赛道我才好按对的标准做。

### 定完赛道做什么

1. 读 `competitions/registry.md` 查该赛道的档案位置
2. 读 `competitions/<赛道>/PROFILE.md` —— 评审偏好、章节骨架、字数、常见失分点
3. 需要看往年获奖作品怎么写的 → 读 `competitions/<赛道>/cases.md`
4. 要出 PPT → 读 `ppt/PLAYBOOK.md` 拿到该赛道的 PPT 策略，再调 `ppt-master`
5. 然后才进下面的六阶段流程

## 这套东西解决什么

中文竞赛材料的失败很少是"内容不够多"，通常败在四处：

1. **结构不认**：模板要求的分节没对齐，评委翻到第三页就找不到研究内容。
2. **图不对**：数据图是 Excel 默认样式，示意图各有各的配色，整篇像拼贴。
3. **排版崩**：图表编号乱、目录页码错、表格跨页裁字、题注和图分家。
4. **语言飘**：通篇"赋能、抓手、闭环、深刻变革"，读完不知道具体做了什么。

外加第五处，只在竞赛里致命：**讲不出来**——文档写得不错，答辩 PPT 一放，评委三分钟没抓到重点。

本技能按这五个失败点组织流程，每一步都有可执行的命令和验收标准。

## 什么时候用

| 你在做的事 | 从这里进 |
|---|---|
| 手里有官方模板.docx，要往里填内容 | 定赛道 → 阶段 2 → 3 → 4 |
| 已经写完了，要改到能交 | 定赛道 → 阶段 4 → 5 → 6 |
| 只有一堆散材料，要从零搭 | 定赛道 → 阶段 1 → 2 → 3 → 4 → 5 → 6 |
| **要做答辩/路演 PPT** | 定赛道 → `ppt/PLAYBOOK.md` → 调 `ppt-master` |
| 要出数据图、示意图 | `figures/SCIENCE-PLOT.md` 或 `pf chart` |
| 要 AI 生成配图/IP/海报 | `figures/AI-IMAGERY.md` |
| 只改文档里某张图 | `references/04-image-ops.md` |
| 只想清掉 AI 味 | `pf style` + `references/07-humanize.md` |
| 交付前最后一遍检查 | `pf qa` + 本文件末尾清单 |

## 六阶段流程

每阶段有**产出**和**门禁**。门禁不过不进下一阶段——返工成本是几何级上升的。

### 阶段 1 · 定基（读懂原始材料）

目标：搞清楚手上有什么、缺什么、谁说了算。

```bash
pf doctor                                  # 环境自检，缺什么一次看清
pf init ./my-proposal                      # 建工作区 fig/ img/ bak/ out/
pf probe 原文件.docx --out out/基线.md      # 结构基线：字数/段落/表/图/标题/图宽
```

要做的事：

- **确认赛道**（第零步已做）与**体裁**。大创申请书和大挑调研报告的骨架完全不同，先读 `competitions/<赛道>/PROFILE.md` 与对应 `templates/outline-*.md`。
- **找权威数据源**。材料里每一个数字都要能指回"哪张表、哪次调研、哪个文件"。先把源数据拢成一份 `data.md`，后面所有图和正文只从它取数。**这一步不做，后面必然出现图与表打架。**
- **列缺口**。哪些字段要本人填（民族、出生年月、指导教师、项目编号），一次性问清，不要边写边问。

门禁：能说出一句话——"这份材料的核心结论是什么，用哪三个数据支撑"。说不出来就回阶段 1。

### 阶段 2 · 搭骨（结构对齐模板）

目标：分节、标题层级、编号体系与官方模板/赛道规范**逐项一致**。

```bash
pf probe 模板.docx --out out/模板结构.md
pf probe 自己的稿.docx --out out/自稿结构.md
```

比对两份基线里的标题列表和表格数量，缺项补齐、多项删掉。中文材料常见坑：

- 模板的表格是**固定结构**（基本情况、经费预算、意见栏），不要新增行，也不要合并单元格。
- 正文若整体装在一个 1×1 表格里（大创申请书就是这样），编辑时**必须穿透表格**——本技能的 `pf` 全部命令都已穿透，自己写脚本时注意别用 `doc.paragraphs`。

体例（经实战验证，见 `references/10-case-dachuang-giep.md` 第 5 节）：

- **章节标题本身不编号**（项目简介／研究目的／…），编号从内容第一层开始：`（一）` → `1.` → `（1）`，最多到第三级。
- 字体分层：一级宋体小四加粗、二级仿宋_GB2312 小四加粗、三级宋体小四加粗。
- 项目命名按"品牌名·对象——地域+动作+手段"，副标题必须一行放得下（12 磅约 30–34 字）。

门禁：标题数量、层级、顺序与模板一致；表格数量一致。

### 阶段 3 · 填肉（内容与论证）

目标：每一节都有"问题—方法—证据—结论"的闭环。

写作纪律（这几条直接决定评委印象）：

- **先给结论再解释**。每节第一段就说明本节得到什么，不要从"随着…的发展"起手。
- **数字必须带口径**。写"103 份有效样本"而不是"大量样本"；写"认知 75.3 分、执行 40.2 分"而不是"存在明显落差"。
- **区分事实与推断**。推断要写明"可能的原因是"，并给出可检验的方向。
- **承认边界**。局限、风险、没做成的地方各写一段，可信度反而上升。
- **不编数据**。缺数据就改论证方式（案例、访谈、文献），不要造数。真要用估算值，标注"估算口径"。

门禁：通读一遍，每一段都能回答"这段想证明什么"。

### 阶段 4 · 配图（数据图、示意图、形象图）

这一步是中文竞赛材料最容易拉开差距的地方。三类图，三种做法：

| 类型 | 用途 | 做法 |
|---|---|---|
| 数据图 | 调研结果、对比、趋势 | `pf chart` 出图，七种图型；要顶刊风格走 `figures/SCIENCE-PLOT.md` |
| 示意图 | 架构、流程、机制、框架 | `pf chart --spec` 的 framework，或用绘图工具后统一配色 |
| 形象图 | IP、海报、界面 | AI 生图（`figures/AI-IMAGERY.md`）+ `pf whitebg` 压白底 + `pf hstack` 合成 |

```bash
pf chart --demo ./fig                  # 先看七种图型长什么样
pf chart --spec fig/图5.json           # 按规格出图
pf images 稿.docx --action list        # 盘点包内图片与尺寸
pf whitebg ip.png                      # 透明背景压白底（不压会变成黑块）
pf hstack a.png b.png --out ab.png     # 两张竖图合成一张横排图
pf recolor 架构图.png --out 改色.png --anchors 0 30 170 215 275 --targets 8 40 190 240 300
```

三条硬纪律：

1. **一篇之内配色要有家族**。同一类图用同一组色，不同类图各给一套色相家族；但**语义色不能动**（绿=合规、红=风险、蓝=授权等级），改了会毁掉含义。
2. **插图宽统一**。整幅宽的图统一到 12.2cm（A4 三厘米边距的正文宽），刻意做小的（截图、甘特图、近景照片）不要动。
3. **单图单题注**。两张图分别插会把后一张的题注挤到下一页，合成一张更稳。

门禁：每张图都能在正文找到"如图 N 所示"的引用；图号连续；图宽中位数落在 12cm 附近。

### 阶段 5 · 修面（排版、编号、目录、文献）

```bash
pf renumber 稿.docx                  # 图/表题注按文档位置重排
pf tables 稿.docx --header           # 表格防跨页裁字 + 表头重复
pf images 稿.docx --action width --cm 12.2
pf text 稿.docx --set "旧串=>新串"    # 批量替换，自带加粗复核
```

目录页码要按渲染结果算，不能用编辑器里的域：

```bash
pf toc 稿.docx                       # 两遍占位法（Windows 需 WPS/Word）
```

参考文献：先查正文有没有 `[n]` 引用，有就必须连正文一起改，只换列表会造成全部编号错位。格式与核实规则见 `references/06-citations.md`。

门禁：`pf qa` 报告里图/表编号连续、正文引用与条目一一对应、无整段加粗。

### 阶段 6 · 交付（自检、导出、留档）

```bash
pf qa 稿.docx --out out/自检报告.md
pf verify 原件.docx 转换件.docx      # 只在做过格式转换时需要
```

导出 PDF 后**逐页看一眼**，重点看三处：图片有没有被裁、题注有没有掉页、目录页码对不对。

交付纪律：

- **不覆盖原文件**。输出永远另存"（修订版）"，原件保留。
- **备份放在 `bak/`**，命名带时间戳，能回退。
- **交付前提醒对方关掉文档**，否则他一保存就覆盖你的成果（`~$xxx.docx` 锁文件就是信号）。
- 交付物：docx + pdf + 自检报告 + 一份改动说明（改了哪几处、为什么）。

## PPT 能力（v2.0 新增）

**本技能不自己实现 PPT，只做编排层**：决定"这个赛道该讲什么、怎么讲"，然后交给 `ppt-master` 生成。

为什么这样分工：`ppt-master` 是上游项目（v6.7.2，145MB，MIT），负责 SVG→原生 DrawingML、模板、动画、叙事视频；竞赛工坊负责**赛道判断**——同一个项目，大创答辩和大挑答辩的 PPT 逻辑完全不同。

```bash
# 先看赛道 PPT 策略
cat ppt/PLAYBOOK.md

# 再加载 ppt-master 技能，按它的路由生成
```

详细流程见 `ppt/PLAYBOOK.md`。要点：

| 赛道 | PPT 定位 | 页数 | 决胜点 |
|---|---|---|---|
| 大创 | 立项答辩，讲"能不能做成" | 12–18 | 可行性、经费、进度、团队 |
| 大挑 | 成果答辩，讲"发现了什么" | 15–20 | 调研方法、数据可信、社会价值 |

## 常用命令总表

```bash
pf doctor                             # 环境自检（简版，看 Python 包与 COM）
pf deps                               # ★ 完整依赖自检：缺什么/怎么装/去哪下（含官方链接）
pf deps --md 环境报告.md               # 写成 markdown，方便发给别人
pf init <dir>                         # 初始化工作区
pf probe <docx> [--out md]            # 结构基线
pf convert <src> [--pdf]              # 旧 .doc / OLE → 真 .docx
pf verify <a.docx> <b.docx>           # 双 PDF 逐页像素比对
pf renumber <docx> [--out]            # 图/表题注重排
pf toc <docx>                         # 目录页码重建
pf tables <docx> [--header]           # 表格防裁字
pf text <docx> --set A=>B             # 批量替换 + 加粗复核
pf images <docx> --action list|width|replace|keepnext
pf chart --spec x.json | --demo dir   # 出图（bar/dumbbell/gantt/donut/heatmap/slope/framework）
pf recolor <img> --anchors .. --targets ..
pf retext <img> --box x0,y0,x1,y1 --text 新字
pf hstack <imgs...> --out out.png
pf whitebg <img>
pf qa <docx> [--out md]               # 交付自检
pf style <md|docx>                    # 去 AI 味检测
```

所有命令加 `--json` 输出结构化结果，便于 agent 直接消费。

## 依赖与移植（别人拿到就能跑）

**本技能设计成"换台电脑也能跑"**：不绑定本机路径，缺什么会自己报出来并给下载链接。

```bash
pf deps                    # 扫一遍：Python 包 / 外部工具 / 中文字体
pf deps --md 环境报告.md    # 写成报告，方便发给队友或换机对照
```

**⚠️ 先确认用的是哪个解释器**：`pf deps` 报告里会打印 `解释器：<路径>`。
本机有多个 Python（`D:\Python\python.exe` 是裸解释器，`~/.workbuddy/binaries/python/envs/default` 才是装了库的共用 venv），
**用错解释器会报"缺 6 项核心依赖"——那不是真缺，是找错了环境**。
报告第一行就写着解释器路径，对照一下即可。

报告分三档：

| 档位 | 含义 | 处理 |
|---|---|---|
| 🔴 必须安装 | 缺了主流程跑不起来 | 按表里的 `pip install` 命令装 |
| 🟡 可选安装 | 缺了降级，不影响主体 | 按需装；每项都写了"缺了会怎样" |
| ✅ 已就绪 | 已装好 | 附版本号与路径 |

**每缺一项都带**：用途说明 + `pip`/`winget` 安装命令 + 官方下载链接。
不写"请自行安装依赖"这种废话。

**外部依赖是可选降级关系**，不是硬绑定：

| 能力 | 本机用什么 | 别人没有怎么办 |
|---|---|---|
| 文档手术 | python-docx | pip 装即可，跨平台 |
| PDF 校验 | pymupdf | pip 装即可，跨平台 |
| 旧 doc 转换 | WPS/Word COM | 没有就用 LibreOffice `soffice --headless` |
| PPT 生成 | ppt-master（独立项目） | `git clone` 上游，或跳过 PPT 只用文档能力 |
| AI 生图 | 本机 SD / AGNES | 都没有就跳过，用真实照片和现成素材 |
| 扫描件 OCR | Windows 内置 OCR | 非 Windows 装 Tesseract；或用任意在线 OCR |

**仓库不分发大文件**：SD 模型（4GB）、ppt-master（145MB）、案例库（1.09GB）
都只给获取方式，不塞进 Git。这也是 `pf deps` 存在的原因——用检测代替打包。

## 硬规则

1. **先定赛道再动手**。没定赛道不许产出任何正式材料（v2.0 新增，最高优先级）。
2. **先验格式再动手**。后缀 `.docx` 不代表是 OOXML；OLE 复合文档要用 COM 转换，转换后必须做 PDF 像素比对证明保真。
3. **新增内容克隆模板**，不要 `add_paragraph(style=...)` 硬造，样式对不上。
4. **遍历必须穿透表格**。中文材料常把全文塞进 1×1 表格，`doc.paragraphs` 会返回空。
5. **图号按文档位置重排**，不要按字符串匹配——总有"图 0""表 2 带空格""题注是普通样式"的漏网之鱼。
6. **目录页码两遍法**。先按最终条目数建目录，渲染取页，再回填；行数不变分页才稳定。
7. **替换文字后必须查加粗**。`set_text` 只保留 run0 格式，run0 若是加粗序号，整段会变粗。
8. **透明 PNG 插 Word 必须压白底**，否则渲染成黑块。
9. **插图 `addnext` 到题注之后**，用 `addprevious` 会把图和题注拆开。
10. **改参考文献前先查正文引用**，有 `[n]` 就一起改，否则编号全错。
11. **不编数据、不编文献**。文献逐条联网核实作者/刊名/年份/卷期，查不到就换一篇。

## 边界

**能做**：结构手术、图表生成、排版修复、文献规范、语言改写、PPT 编排、科研绘图、AI 配图、自检。

**不做**：代替本人编造调研数据与获奖经历；把别人的成果写成自己的；改他人可见的公开页面。

涉及真实人物的肖像、联系方式、证件信息，插入文档前必须确认授权；证件图像不上传公网。
