# 去 AI 味改写提示词

> 复制即用。核心是给**约束**，不是给"去掉 AI 味"这句空话。

---

## 一、单段改写（最常用）

```
把下面这段改写成项目申报书正文。

约束：
1. 保留全部数字、年份、样本量、人名、文件名，不得改动或新增任何数据。
2. 删掉铺垫句与总结句，第一句直接给结论。
3. 形容词一律换成可核对的事实；没有事实支撑的形容词直接删。
4. 超过 60 字的句子拆成两句。
5. 保留学术语体的正式度，不要口语化，不要出现"说白了""其实""咱"这类词。
6. 破折号压到零，改用冒号或断句。
7. 每段只讲一个主张。
8. 不要用"不仅…而且""既…又""一方面…另一方面"这类连锁结构。

输出只给改写后的正文，不要解释改了什么，不要加小标题。

原文：
{粘贴}
```

---

## 二、全文通改（分批进行）

长文不要一次丢进去，按章节分批，每批 2,000–3,000 字。

```
我在改一份 1.5 万字的申报书，现在处理「研究内容」这一节。

按以下顺序处理：
第一步：列出这一节里所有的铺垫句、总结句、万能价值句，只列句子，不要改。
第二步：等我确认后，再逐句给改写建议。

现在做第一步。
```

分两步的价值：先看清问题再动手，避免 AI 一上来就重写整段、把有用的信息也删掉。

---

## 三、学术化（反向操作：太口语 → 太散）

有时是反过来的——初稿写得太随意，需要收紧。

```
把下面这段改成学术书面语。

约束：
1. 口语词换成书面表达：家底→基础数据；底子→基础条件；硬骨头→难点；
   答不上来→缺乏可核对的数据；打通→衔接。
2. 每句补足主语。
3. 数字保留原样，不四舍五入。
4. 不要加"随着…的发展"这类新铺垫。
5. 保留原意的限定条件，不要把"可能"改成"必然"。

原文：
{粘贴}
```

---

## 四、指定病灶改写

已经用检测器定位到具体问题时：

```
这段文字有三个问题，逐个修：

① 空泛归因：「业内普遍认为，保护效果取决于监管强度」——改成点名具体研究。
② 空洞拔高：「具有深远影响」——换成可量化的变化。
③ 公式化排比：「提升了认知、增强了能力、促进了协同」——改成有数据的推进关系。

其余句子不动。输出改后全文。

原文：
{粘贴}
```

---

## 五、自查提示词

改完之后，让对方当评委挑刺：

```
你是一位严格的评审专家，审这份申报书的「立项依据」部分。

只回答三个问题：
1. 这一节的核心结论是什么？用一句话复述。
2. 哪些句子删掉后信息量为零？
3. 哪三个数字是编的、或者没有给出处？

不要夸，不要给鼓励性评价，只指出问题。
```

这一招比"帮我检查一下"有效得多——给具体问题，才能得到具体答案。

---

## 六、哪些不要交给 AI 改

| 内容 | 原因 |
|---|---|
| 具体数值 | 极易被"顺手"改成近似值（62.05 → 62.1），口径就漂了 |
| 文献著录 | 会编造卷期页码，必须人工核 |
| 政策文件名称与文号 | 会写错年份、机关名 |
| 人名与单位 | 会串 |
| 结论性判断 | 改着改着立场就变了 |

**规矩：AI 改语言，人改事实。** 改完必须逐项核对数字与专名。

## 七、验收

```bash
pf style 改后.docx
```

- 得分 ≥80 可交
- 重点看 C3（空泛归因）、A1（铺垫）、C1（拔高）是否清零
- B1（枚举）、D1（破折号）看情况，不要为了分数把正常分类拆散

最后人工通读一遍。工具能抓模式，抓不到"这段话其实什么也没说"。
