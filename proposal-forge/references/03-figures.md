# 03 · 申报书配图

> 一份申报书里的图分三类，做法完全不同。搞混了就会出现"数据图用 Excel 默认样式""示意图颜色一套""形象图黑底"这种典型失败。

---

## 一、先选图型

| 你要表达 | 用哪种图 | 为什么 |
|---|---|---|
| 几个对象的多个指标对比 | **分组柱状图** `bar` | 最不容易误读，评委一眼能比 |
| 两组值的落差（认知 vs 执行） | **哑铃图** `dumbbell` | 落差本身成为视觉元素，比双柱干净 |
| 同一批对象的前后变化 | **斜率图** `slope` | 强调"变化方向"和"变化幅度" |
| 时间进度、里程碑 | **里程碑甘特图** `gantt` | 条形表示区间，圆点表示交付节点 |
| 结构占比（样本构成） | **环形图** `donut` | 只适合 5–7 类，再多就改条形 |
| 多对象 × 多维度得分 | **热力图** `heatmap` | 一张图看出强弱矩阵，不用逐格读表 |
| 架构、分层、流程、机制 | **分层框架图** `framework` | 层间箭头只落在空白带，绝不压字 |

判断标准只有一条：**读图的人要在 5 秒内得到和你写的那段话相同的结论。** 得不出就换图型，不要靠加注释硬救。

---

## 二、出图

```bash
pf chart --demo ./fig          # 七种图型各出一张，先看效果
pf chart --spec fig/图5.json   # 按规格出图
```

规格文件就是一份 JSON，`type` 决定图型，其余字段透传给对应函数：

```json
{
  "type": "bar",
  "out": "fig/图5_四类产品认知与执行对比.png",
  "categories": ["苹果", "梨", "樱桃", "萝卜"],
  "series": [["标志认知", [75.3, 90.2, 66.3, 73.2]],
             ["标准执行", [40.2, 62.1, 40.3, 40.4]]],
  "ylabel": "得分（百分制）",
  "ref_line": 60,
  "family": "teal"
}
```

各图型必填字段：

| type | 必填 |
|---|---|
| `bar` | `categories`, `series`（`[(名称, [值...]), ...]`） |
| `dumbbell` | `categories`, `start`, `end` |
| `gantt` | `tasks`（`[(任务, 起月, 止月, 里程碑月, 注释), ...]`）, `months` |
| `donut` | `labels`, `values` |
| `heatmap` | `row_labels`, `col_labels`, `matrix` |
| `slope` | `points_left`, `points_right`（字典） |
| `framework` | `layers`（`[(层名, [块名...]), ...]`） |

通用可选：`figsize`（默认 6.3×3.4 英寸，对应 A4 正文宽）、`family`（配色家族）、`value_fmt`。

## 三、中文与排版

### 字体

**不要用可变字体。** `NotoSansSC-VF.ttf` 在 matplotlib 里只注册到 weight 100（细体），出来的图细到没法看。用注册了 400/700 的：

```python
plt.rcParams["font.family"] = "Microsoft YaHei"     # C:\Windows\Fonts\msyh.ttc
plt.rcParams["axes.unicode_minus"] = False          # 负号不显示方块
```

Linux 用 `fonts-noto-cjk`，macOS 用 PingFang。字体路径找不到时 `pf doctor` 会报出来。

### 尺寸与分辨率

- `dpi=300`，插入 Word 后缩放不失真。
- `figsize` 宽 6.3 英寸 ≈ A4 正文宽，插进去正好 12–14cm，不用二次缩放。
- 保存用 `bbox_inches="tight"`，去掉多余白边。

### 数值标签

一律加**白色描边**：

```python
from matplotlib import patheffects as pe
fx = [pe.withStroke(linewidth=2.2, foreground="white")]
ax.annotate("75.3", xy, path_effects=fx)
```

原因很实际：图缩到 12cm 宽再看，细标签压在网格线或色块上就糊了。描边是成本最低的可读性修复。

## 四、配色家族

一篇里十几张架构图共用同一套配色，整篇会像一个模子刻出来的。做法是**按类分家族**：

```python
FAMILIES = {
    "teal": ["#1f4e4a", "#2c6e6b", "#4f918c", "#7fb5b0", "#b6d6d2"],
    "clay": ["#5e3524", "#8c5a3c", "#b07a58", "#cfa184", "#e6c8b3"],
    "navy": ["#16283f", "#1f3a5f", "#3a5a80", "#6b88a8", "#a8bdd1"],
    "plum": ["#43263d", "#6b4463", "#8f6486", "#b28fa9", "#d3bccd"],
    "sage": ["#33482f", "#5c7f5c", "#7fa07f", "#a5c0a5", "#c8dcc8"],
    "rose": ["#6b2f3d", "#a05a6b", "#bd7f8e", "#d4a5b1", "#e8c6cf"],
    "gray": ["#2f3437", "#4a5568", "#6f7a86", "#98a2ac", "#c4cbd2"],
}
```

每族是同色相的明度梯度，所以族内关系天然成立；跨族换色只换一家，视觉上就分开了。

**语义色一律不动。** 绿=合规、红=风险、蓝=授权等级、青=通、红=断——这类颜色承载含义，改了会毁掉图的信息。只对纯装饰性配色的图做分化。

对已经做好的位图做家族迁移：

```bash
pf recolor 架构图.png --out 改色.png \
  --anchors 0 30 170 215 275 --targets 8 40 190 240 300
```

`--anchors` 是原图实际用的色相角，`--targets` 是目标色相角，长度必须一致，做环形分段线性映射。

> 关键细节：淡色填充的饱和度往往只有 0.04，**只换色相根本看不出变化**，必须同时把饱和度抬到 0.14 以上（`--sat`，默认 0.14）。白底、黑字、灰线靠饱和度/明度阈值排除，不受影响。

## 五、六种高频视觉缺陷与修法

出图后**逐张看一眼**，别信"应该没问题"。下面是实际踩过的：

| 症状 | 修法 |
|---|---|
| 右侧数值标签互相压 | 按值排序做"错位堆叠"，保证最小间距，用虚线引回原位 |
| 图例压住数据标签 | 图例挪到图外上方：`bbox_to_anchor=(0.5, 1.02)`，并给数据区留 x 轴余量 |
| 热力图 x 轴标签挤成一团 | 标签内换行（`"标志\n认知"`），不是缩小字号 |
| 分组柱太挤 | 减柱宽 `w`，加一条参考线做视觉锚点 |
| 环形图标签压在环上 | 标签放环外（r≈1.3）并带引线；小扇区（<18°）再外推一点避免重叠 |
| 箭头/连接线压住方块文字 | **弧形连接线在窄图里必压字，改直角折线或直线**；箭头只落在层间空白带 |

环形图还有一个隐藏陷阱：百分比直接四舍五入会得到 101%。用最大余数法：

```python
def largest_remainder(values, total=100):
    s = sum(values)
    raw = [v / s * total for v in values]
    floor = [int(x) for x in raw]
    rest = int(round(total - sum(floor)))
    order = sorted(range(len(raw)), key=lambda i: raw[i] - floor[i], reverse=True)
    for i in order[:rest]:
        floor[i] += 1
    return floor
```

## 六、数据一致性：图与表必须同源

真实事故：图里四个产品的"标准执行"全画在 40 分，而表里是 40.24 / 62.05 / 40.27 / 40.44；图上梨的"标志认知"画成 61.6，表里是 90.17。按图上的数算，结论会从"认知高、执行低"翻转成"认知低于执行"，与全文判断相反。

**规矩：先定一份 `data.md` 做唯一权威源，图和表都从它取数。** 发现图与表不一致时，先问"以哪个为准"，不要自己挑一个改——改错方向等于把结论改反。

## 七、示意图（架构/流程）的另一条路

`pf chart` 的 `framework` 只解决"分层块状"这一类。更复杂的泳道图、机制图、UI 示意图，两条路：

1. **绘图工具**（draw.io / Figma / PPT）画好导出 PNG，插入后用 `pf recolor` 统一到本文配色家族。这条路对复杂图更快。
2. **AI 生图**只适合形象图与海报（见 `04-image-ops.md` 与 `templates/prompt-figures.md`），**不要**用 AI 生图做含有精确文字与数据的架构图——文字会糊、数字会错。

判断标准：图里的文字需要被读者逐字读清吗？需要 → 工具画；不需要 → 可以 AI 生成。
